[ISSUE-SP-01] BACK-03: Notification Entity Lacks Target Recipient User ID
- Severity: Medium
- Current Status: STILL PRESENT
- Category: Backend Data Model / Privacy Isolation
- Affected Files:
  * `Alumni_Backend/src/main/java/com/alumni/management/notification/entity/Notification.java`
  * `Alumni_Backend/src/main/java/com/alumni/management/notification/service/NotificationService.java`
- Evidence:
  The `Notification` entity contains fields `id`, `title`, `message`, `timestamp`,
  and `isRead`, but does not contain a foreign key `recipient_user_id` or `recipient_email`.
- Impact:
  All notifications currently operate in broadcast mode across the entire platform.
  A user cannot receive private or targeted administrative notices without every
  other user also receiving them.
- Reproduction:
  1. Inspect `Notification.java` entity class.
  2. Query `GET /api/notifications` from two different user accounts.
  3. Both accounts receive identical notification objects.
- Recommended Fix:
  In a future scheduled release, introduce a database migration adding
  `recipient_user_id BIGINT REFERENCES users(id)` and an `is_broadcast BOOLEAN DEFAULT FALSE`
  flag to support both targeted and system-wide announcements safely.

[ISSUE-PF-02] BACK-02: String-Based Salary Storage (VARCHAR)
- Severity: Low
- Current Status: PARTIALLY FIXED
- Category: Database Storage Format
- Affected Files:
  * `Alumni_Backend/src/main/java/com/alumni/management/jobpost/entity/Job.java` (Line 29)
  * `GLS-Connect-Frontend/lib/utils/salary_helper.dart`
- Evidence:
  Salary continues to be stored as `VARCHAR(50)` (e.g., "8 LPA", "₹12 LPA").
  Salary parsing and boundary filtering operate in Flutter memory via `SalaryHelper`
  (verified with 20 passing unit tests).
- Impact:
  SQL-level `BETWEEN` queries cannot be executed on the backend database. All job
  filtering must be executed on the client device.
- Recommended Fix:
  Add an optional numeric column `salary_lpa NUMERIC(5,2)` to table `jobs` in the
  database and populate it automatically during job creation.

[ISSUE-PF-06] BACK-04: Duplicate User Listing Endpoints
- Severity: Low
- Current Status: PARTIALLY FIXED
- Category: API Design
- Affected Files:
  * `UserController.java` (`/api/users`)
  * `AdminController.java` (`/api/admin/users`)
- Evidence:
  Two separate controllers expose user lists with different DTO shapes.
- Impact:
  Security is verified (`@PreAuthorize("hasRole('ADMIN')")` protects admin data),
  but API consumers must target different endpoints for administrative user views.
- Recommended Fix:
  Consolidate into a unified paginated user query service with role-filtered views.

[ISSUE-PF-07] ACC-01 / ACC-02 / ACC-03: Accessibility & Visual Density
- Severity: Low
- Current Status: PARTIALLY FIXED
- Category: Accessibility
- Affected Files:
  * `lib/widgets/job_card.dart`
  * `lib/widgets/event_card.dart`
  * `lib/screens/navigation/main_navigation.dart`
- Evidence:
  Action chips use `VisualDensity.compact`, yielding touch targets around 36x36 dp,
  which is below the WCAG 48x48 dp touch target recommendation.
- Impact:
  Users with motor difficulties may experience reduced tap accuracy.
- Recommended Fix:
  Increase touch target padding on chip containers.
