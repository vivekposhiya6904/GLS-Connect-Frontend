SECTION 2 - EXECUTIVE SUMMARY
================================================================================

A comprehensive cross-module audit of the GLS Connect Alumni Management
System was conducted to evaluate consistency across the four user modules:
Student, Alumni, Faculty, and Admin.

2.1 Key Audit Statistics:
    - Total Modules Inspected:                    4
    - Total Screens & Widgets Inspected:          35+
    - Total Backend Controllers Inspected:        12
    - Total Database Entities Inspected:          14
    - Total Confirmed Defects:                    4
    - Total Consistency Issues:                   7
    - Total Potential Issues (Runtime-Dependent):  3
    - Total Intentional Role-Based Differences:   5
    - Total Improvement Recommendations:          8

2.2 Issue Breakdown by Priority:
    - P0 (Critical - Security / Crash / Data Loss): 0
    - P1 (High - Major Functional Inconsistency):   3
    - P2 (Medium - Noticeable UI/UX Inconsistency): 7
    - P3 (Low - Styling / Minor Polish / Dead Code): 4

2.3 Summary of Most Critical Discoveries:
    1. Student Profile Route Disconnect (P1 - Functional Mismatch):
       In MainNavigation, a user with role STUDENT is routed to
       AlumniProfileScreen. The form displays alumni-specific fields (Company,
       Work Experience, Designation), and the backend endpoint
       (/api/alumni/profile) enforces @PreAuthorize("hasRole('ALUMNI')"),
       causing save operations by students to be rejected. There is currently
       no student-specific profile entity or screen in the system.

    2. Create (+) Action Button Visible to Students (P1 - Permission Drift):
       MainNavigation renders the central 'Create (+)' action button for all
       non-admin users, offering 'Post Job' and 'Create Event'. When a student
       attempts to post a job, backend JobService throws an authorization
       exception ("Only alumni, faculty, and admin can create job posts").
       The UI exposes actions the student has no permission to perform.

    3. Directory Profile Filtering Logic Drift (P1 - Logic Discrepancy):
       In Alumni and Faculty modules, ProfileList discards registered users who
       have not filled in all optional extended fields (isFilled check), and
       only searches by userName. In the Student module, ProfileList displays
       all registered users with graceful fallbacks and searches across name,
       company, designation, department, degree, and skills.

    4. Inconsistent Scaffold Background Colors (P2 - Visual Inconsistency):
       Student HomeScreen uses Color(0xFFF5F6FA) (cool grey), whereas Alumni,
       Faculty, and Admin HomeScreens use Color(0xFFF4F7FF) (soft blue-tint).
       ProfileDetailScreen uses Color(0xFFF8F9FA).

    5. Inconsistent Search Bar Clear Buttons and Prefix Colors (P2 - UI Drift):
       Student directory search has a clear button (Icons.clear) and blue search
       icon (0xFF1A3A8F). Alumni directory search lacks a clear button and uses
       an unstyled grey icon. Admin user search has a clear button, radius 10,
       and soft blue fill (0xFFF4F7FF).

    6. Dead Code - Orphaned Community Feed Screens (P3 - Code Hygiene):
       lib/screens/community/community_screen.dart and create_post_screen.dart
       are never routed to from any navigation bar or router in the application.

SECTION 5 - UI/UX INCONSISTENCIES
================================================================================

5.1 UI-01: Scaffold Background Color Mismatch
    - Student HomeScreen:   Color(0xFFF5F6FA) [Line 31]
    - Alumni HomeScreen:    Color(0xFFF4F7FF) [Line 38]
    - Faculty Dashboard:    Color(0xFFF4F7FF) [Line 23]
    - Admin HomeScreen:     Color(0xFFF4F7FF) [Line 386]
    - Search Screen:        Color(0xFFF5F6FA) [Line 332]
    - Profile Detail:       Color(0xFFF8F9FA) [Line 67]
    Impact: Subtle visual jarring when navigating between Student and Alumni
    screens. Standard palette should define a single surfaceBackground token.

5.2 UI-02: Search Bar Border Radius & Color Divergence
    - Student/Alumni Jobs:  fillColor: Colors.white, radius: 12.0
    - Student/Alumni Events:fillColor: Colors.white, radius: 12.0
    - Admin Users:          fillColor: Color(0xFFF4F7FF), radius: 10.0 [Line 587]
    - Chat Screen Search:   fillColor: transparent, underline border
    Impact: Lack of unified search bar styling across administrative and consumer
    screens.

5.3 UI-03: Search Bar Suffix Clear Button Inconsistency
    - Student Directory:    Has suffixIcon (Icons.clear) when text is non-empty.
    - Admin Users:          Has suffixIcon (Icons.clear) when text is non-empty.
    - Student Jobs:         NO clear button.
    - Alumni Jobs:          NO clear button.
    - Alumni Events:        NO clear button.
    - Alumni Directory:     NO clear button.
    Impact: Inconsistent user experience; users must manually delete search
    queries character-by-character on several screens.

5.4 UI-04: Directory Search Icon Color Inconsistency
    - Student Directory:    prefixIcon: Icon(Icons.search, color: Color(0xFF1A3A8F))
    - Alumni Directory:     prefixIcon: Icon(Icons.search) [Default theme grey]
    - Admin Users:          prefixIcon: Icon(Icons.search, color: Colors.grey)
    Impact: Student module uses brand blue for icon; Alumni uses unstyled grey.

5.5 UI-05: Notification Icon Absent from Faculty and Admin AppBars
    - Student HomeScreen:   Includes notification bell icon in AppBar.
    - Alumni HomeScreen:    Includes notification bell icon + unread count badge.
    - Faculty Dashboard:    NO notification icon in AppBar.
    - Admin HomeScreen:     NO notification icon in AppBar.
    Impact: Faculty users cannot view notification feed from their dashboard
    app bar, even though notifications are supported in backend.

5.6 UI-06: Third-Party Public Image Dependency in Event Cards
    - File: lib/widgets/event_card.dart [Line 34]
    - Code: "https://picsum.photos/600/300?random=${event.title}"
    Impact: When an event has no imageUrl, EventCard queries picsum.photos. If
    network is slow, offline, or restricted, the card hangs or renders broken
    image icons. Should use a local bundled asset fallback.

5.7 UI-07: Deprecated withOpacity() vs Modern withValues() API Usage
    - Student HomeScreen:   Colors.amber.withOpacity(0.2) [Line 51]
    - Alumni HomeScreen:    Colors.amber.withOpacity(0.2) [Line 56]
    - Faculty Dashboard:    Colors.amber.withOpacity(0.2) [Line 40]
    - Admin HomeScreen:     Colors.amber.withValues(alpha: 0.2) [Line 402]
    - JobCard / EventCard:  withValues(alpha: ...) [Modern Flutter SDK]
    Impact: Inconsistent SDK method usage; older withOpacity() generates lint
    warnings on newer Flutter SDKs.

    - Consequence:
      Students cannot create jobs (backend JobService throws RuntimeException:

    - Location: lib/screens/dashboard/alumni_home_screen.dart [Lines 1039-1055]
    - Details:
      Alumni _ProfileListState implements an isFilled predicate:
      final isFilled = (alumni.degree != null && alumni.degree!.isNotEmpty) ||
                       (alumni.companyName != null && alumni.companyName!.isNotEmpty) ||

      Newly registered alumni or faculty who have not yet populated their extended

    - Location: lib/screens/dashboard/student_home_screen.dart [Lines 125-275]

      Alumni and Faculty EventList has a full search bar and department modal sheet.
    - Severity: P2 (Medium)

6.5 FUNC-05: Redundant Client-Side Job Filtering in Alumni My Activity

SECTION 7 - BACKEND, API & DATA INCONSISTENCIES
================================================================================

7.1 BACK-01: No Student Profile Entity or Table in PostgreSQL
    - Location: Alumni_Backend (entities and repositories)
    - Details:
      PostgreSQL schema contains:
      * alumni_profiles (id, user_id, batch_year, company_name, designation, ...)
      * faculty_profiles (id, user_id, department, designation, ...)
      There is NO student_profiles table or StudentProfile entity.
      When a student registers, an entry is inserted into the users table with
      role STUDENT, but no profile record is created.
    - Impact: Student profile data cannot be persisted or retrieved cleanly.

7.2 BACK-02: String-Based Salary Storage (VARCHAR) in PostgreSQL
    - Location: Alumni_Backend Job.java [Line 29] / jobs.salary VARCHAR
    - Details:
      Salary is stored as a VARCHAR string (e.g., "8 LPA", "₹12 LPA").
      Because there is no numeric column (e.g. salary_lpa NUMERIC(5,2)), the
      backend cannot execute SQL-level salary range queries (WHERE salary BETWEEN
      3.0 AND 5.0). All salary range filtering must be executed in memory by
      Flutter using SalaryHelper.
    - Assessment: Works reliably with current dataset; documented for future
      database optimization.

7.3 BACK-03: Notification Entity Missing Target User ID
    - Location: Alumni_Backend Notification.java
    - Details:
      Notification entity stores title, message, timestamp, and isRead, but lacks
      a recipient_user_id column. All notifications appear to be broadcast-style
      rather than user-specific.

7.4 BACK-04: Duplicate User Listing Endpoints
    - Location: UserController.java (/api/users) vs AdminController.java (/api/admin/users)
    - Details:
      AdminController defines GET /api/admin/users guarded by @PreAuthorize("hasRole('ADMIN')").
      UserController defines GET /api/users which is unpartitioned.

SECTION 9 - ACCESSIBILITY & RESPONSIVENESS

9.1 ACC-01: Fixed-Height Bottom Navigation Bar (Small Screens)
    - File: lib/screens/navigation/main_navigation.dart [Line 158]
    - Code: SizedBox(height: 62, child: ...)
    - Issue: On very compact devices (e.g., iPhone SE or Android devices with

      if system text scale exceeds 1.3x.

9.2 ACC-02: Compact Visual Density on Action Chips
    - Files: lib/widgets/job_card.dart, lib/widgets/event_card.dart
    - Issue: Chips use VisualDensity.compact, yielding touch targets smaller than
      the recommended 48x48 dp minimum accessibility standard.

9.3 ACC-03: Lack of Semantic Labels on Icon Buttons
    - Files: Filter buttons in student_home_screen.dart and alumni_home_screen.dart
    - Code: GestureDetector(child: Container(child: Icon(Icons.tune)))
    - Issue: Screen readers (TalkBack / VoiceOver) announce "button" or "unlabeled"
      because no tooltip or Semantics widget is provided.

SECTION 11 - LEGITIMATE ROLE-SPECIFIC DIFFERENCES
================================================================================

The audit confirmed that the following differences across modules are
intentional business requirements and MUST NOT be removed:

11.1 Job and Event Authoring Permissions:
     - Student: View-only access to Jobs and Events feeds. Students cannot post
       jobs or schedule university events.
     - Alumni: Authorized to post jobs (PostJobScreen) and schedule events
       (CreateEventScreen).
     - Faculty: Authorized to post jobs (PostJobScreen) and schedule events
       (CreateEventScreen).
     - Admin: Full CRUD access over all jobs and events in the system.
     * Rationale: Standard academic role hierarchy. Enforced by backend
       JobService.java line 98 and EventService.java line 46.

11.2 Community Posts in 'My Activity':
     - Alumni: Includes 3 sub-tabs ('My Posts', 'My Events', 'My Jobs').
     - Faculty: Includes 2 sub-tabs ('My Events', 'My Jobs') via showPosts: false.
     - Student: Includes 2 sub-tabs ('My Events', 'My Jobs').
     * Rationale: Alumni are the primary creators of community networking posts.
       Faculty and students consume feeds without personal community posting.

11.3 Admin Management and Moderation Portal:
     - AdminHomeScreen is a standalone portal without a bottom navigation bar.
     - It features overview metric cards (Total Users, Active Jobs, Events),
       user provisioning (Create User, role assignment, department allocation),
       and delete confirmations.
     * Rationale: Administrative operations are strictly segregated by Spring
       Security (ROLE_ADMIN) and DashboardRouter.

11.4 Top-Right AppBar Actions:
     - Student and Alumni: Notification bell with unread badge.
     - Admin: Red logout confirmation icon button.
     * Rationale: Admin portal has a streamlined desktop-style header.
