2. FAILURES ENCOUNTERED DURING TESTING & HOW THEY WERE ADDRESSED
--------------------------------------------------------------------------------

Failure 1:
- Symptom: `A RenderFlex overflowed by 425 pixels on the right` during JobCard 320px width test.
- Root Cause: Unconstrained Row inside Wrap prevented text from wrapping or truncating.
- Resolution: Wrapped Wrap in LayoutBuilder and enclosed each chip in ConstrainedBox(maxWidth: constraints.maxWidth)
  with Flexible(child: Text(..., maxLines: 1, overflow: TextOverflow.ellipsis)). Test passed immediately.

Failure 2:
- Symptom: `A RenderFlex overflowed by 112 pixels on the right` in MainNavigation at 320px width.
- Root Cause: AppBar title in HomeScreen/StudentHomeScreen/FacultyDashboard used rigid Spacer()
  forcing children to exceed the ~232px available width constraint when notification actions were present.
- Resolution: Replaced rigid Spacer() with Flexible title text and compact role badge. Test passed.

Failure 3:
- Symptom: `UnimplementedError: close`, `contentLength=`, `addStream`, `isRedirect`, `redirects` in test HTTP mock.
- Root Cause: Dart's http.Client uses IOClient which invokes full HttpClientRequest and HttpClientResponse lifecycle.
- Resolution: Implemented complete MockHttpClientRequest and MockHttpClientResponse handling in test harness.
  Real API services and models verified cleanly.

Failure 4:
- Symptom: Warning that tap() on Reset Search & Filters hit-tested off-screen in 290px keyboard viewport.
- Root Cause: The button was scrollable inside SingleChildScrollView but slightly below the top of the simulated keyboard.
- Resolution: Called `tester.ensureVisible()` before tapping, confirming smooth scrollability and reachability.
