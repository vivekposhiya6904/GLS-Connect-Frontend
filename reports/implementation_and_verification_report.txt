and unify the UI/UX design across Student, Alumni, Faculty, and Admin modules.

2. CONFIRMED DEFECTS ADDRESSED
================================================================================

[DEFECT P1-A] Student Profile Routing and Persistence Mismatch
- Problem: Students navigating to Profile in `MainNavigation` were directed to
  `AlumniProfileScreen`. Submitting changes triggered `/api/alumni/profile`, which
  demanded the `ROLE_ALUMNI` authority, throwing HTTP 403 Forbidden and failing to save.
- Correction:
  - Backend: Implemented `StudentProfile` entity mapped to `student_profiles`,
    `StudentProfileDto`, `StudentProfileRepository`, `StudentProfileService`, and
    `StudentProfileController` under `com.alumni.management.student`.
  - Frontend: Implemented `StudentProfileModel`, `StudentProfileService`, and
    `StudentProfileScreen`.
  - Routing: Updated `MainNavigation` to route `STUDENT` -> `StudentProfileScreen`,
    `ALUMNI` -> `AlumniProfileScreen`, and `FACULTY` -> `FacultyProfileScreen`.
  - Also updated `ProfileDetailScreen` to support viewing student profiles.

[DEFECT P1-B] Invalid Student Create (+) Actions
- Problem: The bottom navigation bar displayed a global Create (+) button to Student
  users, offering "Post Job" and "Create Event", which the backend correctly rejected.
- Correction:
  - In `MainNavigation`, conditionally evaluated `userRole == "STUDENT"`.
  - When the user is a student, the middle Create (+) button is omitted from both the
    BottomNavigationBar items and navigation indexing (navigating directly between
    Home, Chat, and Profile).
  - Alumni and Faculty continue to have full access to their permitted publishing actions.

[DEFECT P1-C] Alumni & Faculty Directory Incompleteness & Search Divergence
- Problem: `ProfileList` in `alumni_home_screen.dart` filtered out accounts where
  `isFilled` was false, hiding real alumni/faculty who had not completed optional fields.
  Additionally, search was restricted to name and company only.
- Correction:
  - Removed `!isFilled` drop filter; all eligible active users are displayed.
  - Missing fields render safe fallbacks (e.g., "Not specified", "Faculty Member").
  - Multi-field search implemented across name, company, designation, department,
    degree, specialization, skills, and city.

[DEFECT P2-A] Inconsistent Scaffold Background Colors
- Problem: Student dashboard used `#F5F6FA`, Alumni/Faculty used `#F4F7FF`, Profile detail
  used `#F8F9FA`, creating jarring visual transitions between screens.
- Correction:
  - Standardized primary background to `#F4F7FF` across dashboards, profile screens,
    community screens, and notifications.

[DEFECT P2-B] Search Field Discrepancies
- Problem: Differing icon colors (blue vs grey), missing clear/reset actions, inconsistent
  border radii and focus outlines.
- Correction:
  - Standardized search inputs with 12px border radius, `#1A3A8F` brand prefix icon,
    focused border highlight, and an interactive clear button (`Icons.clear_rounded`)
    that immediately resets the filter query.

[DEFECT P2-C] Public Random Image Dependencies in Event UI
- Problem: Event cards and detail views used `https://picsum.photos/600/300` when event
  images were missing, displaying arbitrary unrelated images.
- Correction:
  - Implemented high-fidelity branded fallback containers using university primary
    gradients (`#1A3A8F` to `#2E5BBA`), calendar/event iconography, and dynamic
    target department badges.

[DEFECT P3-A] Student Events Missing Search and Department Filters
- Problem: Student Events feed lacked keyword search and department filtering
  available in Alumni and Faculty feeds.
- Correction:
  - Unified `EventsPage` in `student_home_screen.dart` to use the standardized `EventList`,
    giving Students full access to search and department filters while preserving
    read-only event registration actions.

[DEFECT P3-B] Salary Filter LPA Boundary & Parsing Integrity
- Verified: `SalaryHelper` filter ranges (`All`, `0-3 LPA`, `3-5 LPA`, `5-8 LPA`,
  `8-12 LPA`, `12+ LPA`) were validated across all 20 test cases in
  `salary_filter_consistency_test.dart`.
